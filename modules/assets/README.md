# ui-assets

Embedded fonts, icons and photos for UI fixtures, tests and demos: two Noto Sans subsets, Geist
and Geist Mono (the devtools' faces), the
toolbar and card icons, an animated orbit SVG, and procedural photos. They were the
[graphics demo](https://github.com/silk-lang/nonstd/tree/7d6c3693a9ad1fec24127985626ab4224f9f1995/examples/graphics-demo)'s assets, and moved here because ui-tree's fixtures,
ui-app tests and several demos use them too. Import `assets` for typed accessors (`regularFont`,
`icon(index)`, `photo(index)` and the icon constants).

Fonts are subsets of Noto Sans (SIL Open Font License, `assets/fonts/Noto-LICENSE-OFL.txt`)
and of the Geist and Geist Mono variable fonts (SIL Open Font License,
`assets/fonts/Geist-LICENSE-OFL.txt`), cut to Latin, punctuation and arrows with fontTools
`subset`, keeping their weight axis (100 to 900).
Icons were drawn for the graphics demo. Photos are committed procedural landscapes. The optional
`silk task generate-photos` authoring task requires ImageMagick 7's native `magick` executable on
`PATH`; it is never part of a normal build or check. Silk renders the twelve original palettes,
160×120 sky gradients, positioned suns, two sampled sine-wave hill layers and smoothing kernel.
Even-numbered scenes are RGB PNGs compressed at level 9; odd-numbered scenes are JPEGs at quality
82 with optimized coding. Run `silk task embed-assets` afterward to embed the new photos.

The authoring algorithm is deterministic for a fixed Silk/ImageMagick toolchain, but is not
byte-identical to the former Pillow tool: circles use pixel-center distance coverage, hill edges
use linear interpolation between the original four-pixel samples, color averages round half up,
and the glow uses a separable Gaussian with sigma 9 truncated at three sigma instead of Pillow's
extended-box approximation. Native encoder versions can also change compressed bytes.
Existing committed photos are unchanged until the authoring task is explicitly invoked.

`src/generated_assets.silk` embeds the `.ttf` fonts, `.svg` icons and `.png`/`.jpg` photos
under `assets/` as byte strings. Regenerate it with `silk task embed-assets` from the repository
root after changing an asset. `silk task embed-assets --check` compares the generated bytes
without writing and fails if the committed file is stale. It exists because
`silk.build.source.Source.read` in a dependency package, at Silk 0.1.0-dev.45 (first seen in dev.44), resolves the path
under that package's `src/` and lexes the file as Silk, so assets cannot be read at build time
by a library.
